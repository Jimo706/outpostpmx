# OutpostX Date/Time Policy

Document Status: Draft
Applies To: OutpostX Core Messaging System
Last Updated: 2026-05-18

## 1. Purpose

This document defines the OutpostX policy for storing, parsing, displaying, and printing date/time values associated with messages.

The primary goals are:

- Preserve original BBS-provided message timestamps.
- Avoid unintended timezone conversion.
- Clearly distinguish UTC timestamps from local/BBS timestamps.
- Normalize timestamp string formatting.
- Maintain compatibility with existing databases and message archives.

## 2. General Principles

OutpostX distinguishes between:

- OutpostX-induced timestamps
- Date/times created by OutpostX itself.
- BBS-reported timestamps
- Date/times supplied by external BBS systems such as KPC3, JNOS, BPQ, FBB, or Winlink.

OutpostX does not assume all BBS systems operate in UTC.

## 3. Storage Rules
### 3.1 Timestamp Format

All stored timestamps use ISO-style formatting.

    Examples:

    2026-05-19T02:34:25Z
    2026-05-18T19:32:51

### 3.2 UTC Timestamps

Any timestamp ending with:

    Z

    or containing an explicit UTC offset:

    +00:00
    -07:00

    is treated as an absolute UTC-based timestamp.

    Examples:

    2026-05-19T02:34:25Z
    2026-05-19T02:34:25+00:00

### 3.3 Local/BBS Timestamps

Any timestamp without a timezone marker is treated as a local/BBS timestamp.

    Example:

    2026-05-18T19:32:51

This indicates:

- local BBS time
- unknown timezone
- legacy local format
- or non-UTC source time

OutpostX does not implicitly convert such timestamps to UTC.

## 4. OutpostX-Induced Timestamps

The following timestamps are generated by OutpostX itself:

- outbound message sent time
- inbound message receive/store time
- internal processing timestamps

These timestamps SHALL be stored as UTC ISO strings with trailing Z.

    Examples:

    sent_at = 2026-05-19T02:34:25Z
    rcvd_at = 2026-05-19T02:34:33Z

## 5. BBS-Reported Timestamps

BBS-reported timestamps are preserved as reported by the originating BBS.

OutpostX normalizes only the string shape.

OutpostX SHALL:

- preserve UTC/Z markers when explicitly supplied
- preserve local/no-timezone timestamps when supplied
- avoid guessing timezone offsets
- avoid silently converting local BBS times into UTC

    Examples:

    Source	Example	Stored As
    BPQ	2026-05-19T02:34:25Z	UTC
    KPC3	05/18/26 19:32	2026-05-18T19:32:00
    JNOS	05/18 19:32	2026-05-18T19:32:00

## 6. Display Rules

OutpostX display surfaces SHALL clearly label the timestamp basis.

### 6.1 UTC Display

UTC timestamps SHALL display:

    UTC

    Example:

    2026-05-19 02:34 UTC

### 6.2 Local/BBS Display

Non-Z timestamps SHALL display:

    Local

    Example:

    2026-05-18 19:32 Local

## 7. Display Locations

The following UI surfaces use the date/time display policy:

- Message Listing
- Message Header
- Message Print Preview
- Printed Messages

## 8. Database Compatibility

This policy intentionally avoids database schema migration.

Existing databases remain valid.

Legacy timestamps without timezone markers continue to be interpreted as local/BBS timestamps.

## 9. Future Considerations

Possible future enhancements include:

- user-selectable local timezone conversion
- explicit timezone storage
- BBS timezone configuration
- UTC-to-local rendering preferences
- export/import timezone metadata
- message synchronization across systems

These enhancements are outside the scope of the current implementation.

## 10. Summary

OutpostX date/time handling follows these core rules:

- OutpostX-created timestamps use UTC with Z.
- BBS-reported timestamps are preserved.
- ISO formatting is used consistently.
- UTC vs Local is explicitly labeled in displays.
- No implicit timezone guessing or conversion occurs.
