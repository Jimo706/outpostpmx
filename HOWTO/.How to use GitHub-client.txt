# Chapter 3 - Committing Changes
CREATE A RELEASE

1. Review the Repository
Before creating a commit, review the current repository status.
	git status

Confirm that:
* Only the expected files have been modified.
* No temporary files have been added.
* No build artifacts are included.
* Documentation updates have been staged when appropriate.

2. Stage the Changes
For most OutpostPMX development sessions, all completed work is staged together.
	git add .

If necessary, individual files may also be staged separately.  Example:
	git add outpostx/services/app_paths.py

3. After staging, verify the results.
	git status

4. Create the Commit
	git commit -m "Implement configurable notification sounds"
	or
	git commit	>>> Opens an editor

Good examples include:

	Fix AGWPE connection timeout
	Add Hot Key Profiles
	Improve message editor layout
	Update Linux build procedure
	Correct station profile validation	

# Chapter 4 - Creating a Release Tag
5. Verify the Commit
	git status

6. Creating a Release Tag
	A release tag is a permanent label attached to a specific Git commit.

	git tag v2026.07.0-beta1
	git tag -a v2026.08.1-beta -m "OutpostPMX 2026.08.2 Beta"

	The first command creates the tag locally.\
	The second command creates an annotated which are generally recommended for official releases.\
	    The -a creates an annotated tag, and -m stores a description with it.

7. Verify the tag.
	git tag
	
	The newly created tag should appear in the list.

8. Push the Tag to GitHub
	Upload the tag.

	git push origin v2026.07.0-beta1
